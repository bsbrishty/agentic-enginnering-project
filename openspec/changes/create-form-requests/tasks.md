## 4. `StoreTestimonialRequest`

- [x] 4.1 Create `app/Http/Requests/StoreTestimonialRequest.php` extending `FormRequest`.
- [x] 4.2 Implement `authorize()` returning `true` (the public submission endpoint is open; per-space rate limiting and spam protection are middleware concerns).
- [x] 4.3 Implement `rules()` per `docs/data-model.md` §8.2:
  - `space_id`: derived from the route, not validated here (the controller resolves the space from the URL)
  - `submitter_name`: `required|string|max:255`
  - `submitter_email`: `required|email|max:255`
  - `submitter_company`: `nullable|string|max:255`
  - `submitter_social_links`: `nullable|array`
  - `submitter_social_links.*`: `nullable|url|max:2048`
  - `testimonial_text`: `required|string|max:10000`
  - `rating`: `nullable|integer|min:1|max:5`
  - `profile_photo_url`: `nullable|url|max:2048`
  - `field_values`: `required|array`
  - `consent_state`: `required|in:granted,declined,not_asked`
  - `is_favorite`, `is_wall_of_love`, `is_hidden`: NOT validated — owner-only fields, set by the dashboard, not the public form
  - `submitted_at`: NOT validated — set by the controller to `now()`
- [x] 4.4 Add a class-level docblock explaining that `consent_state` MUST be `'granted'` for the testimonial to be eligible for the Wall of Love (data-model §6), and that the controller-layer checks this invariant before persisting.
- [ ] 4.5 Verify with a feature test: `POST /c/{token}` with valid payload creates a row; missing `consent_state` returns 422; an invalid `consent_state` value returns 422.

> File written: `app/Http/Requests/StoreTestimonialRequest.php`

## 6. End-to-End Verification

- [ ] 6.1 Write a feature test for each form request covering: valid payload passes, missing required field returns 422 with the correct key, invalid enum value returns 422, invalid format (email, URL, regex) returns 422, and the auto-generated identifiers are NOT overwritten by request input.
- [ ] 6.2 Verify that `UpdateSpaceRequest` does not include `public_slug` or `public_token` in its rules and that a `PATCH` request including those fields does not change the values on the model.
- [ ] 6.3 Verify that `StoreTestimonialRequest` does not accept `is_wall_of_love` or other owner-only flags, even if the client sends them — Laravel ignores unknown fields by default when using `validated()`.
- [ ] 6.4 Verify that `StoreEmbedConfigRequest` does not accept `public_id` from input, and that a generated UUID v4 is always assigned by the model.
- [ ] 6.5 Confirm that the consent invariant check (consent_state must be `'granted'` for Wall of Love eligibility) is implemented in the controller or policy layer, not in the form request. The form request only validates the *value* of `consent_state`, not its policy implications.
